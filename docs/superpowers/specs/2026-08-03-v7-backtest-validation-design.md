# V7 模型历史回测验证 — 设计文档

日期: 2026-08-03

## 背景

服务器运行的 V7.0-causal-ml-balanced 影子机器人（LightGBM，102 特征，阈值 0.555，10 分钟事件合约）实盘 6 天（7/29-8/3）139 笔，胜率 57.6%，总 PnL +50（盈亏平衡线 55.6%）。关键发现：

- UP 方向 80 笔 50% 胜率（-80 PnL），任何阈值下都亏
- DOWN 方向 59 笔 67.8% 胜率（+130 PnL）
- 94% 信号置信度集中在 [0.55, 0.58)，≥0.58 的 8 笔胜率 87.5%
- 风险：6 天样本恰好是 ETH 下跌周（1912→1864），"UP 失效"可能是行情假象

目标：用冻结模型做 2.5 年历史回测，验证 UP 是否系统性失效、确定各方向最优阈值，避免过拟合 6 天实盘。

## 方法

### 1. 数据

- Binance REST 拉取 ETHUSDT 5m/15m/1h 已收盘K线，2024-01-01 至 2026-08-03
- 代理支持（本机 127.0.0.1:7892），失败自动重试
- 5m 约 27 万根 → ~280 次分页请求

### 2. 特征构建（向量化，与实盘等价）

复用 `v7_feature_engine.py` 的 `_build_base_features` / `_add_timeframe_features`：
- 5m 全历史一次性向量化计算（EMA/RMA/rolling 均为因果指标，index i 的值只依赖 ≤i 的数据，与实盘逐行计算等价）
- 15m/1h 特征同样全量计算，用 searchsorted 按 open_time 对齐"信号时刻已完整收盘"的K线
- 对齐后拼接 102 特征行，顺序与模型配置一致

### 3. 交易模拟（完全复现实盘规则）

- 5m 收盘（open_time + 5min ≤ 信号时刻）计算信号
- prob_up ≥ 0.555 → up；≤ 0.445 → down；否则跳过
- min_atrp = 0.0005 过滤
- cooldown = 1（与上一信号间隔 ≥ 2 根 5m 收盘）
- 下一根 5m 开盘价入场，再下一根收盘价结算；胜 = 方向与价格变动一致
- 风控：日内（北京时间）最大信号 50、亏损 -75 熔断
- stake 25、payout 0.8，PnL = WIN +8 / LOSS -10

### 4. 输出报告

1. **验证段对齐**：回测 7/29-8/3，与实盘 139 笔 CSV 对比（笔数/胜率/方向分布），不一致则排查
2. **阈值扫描**：0.555 / 0.56 / 0.57 / 0.58 / 0.59 / 0.60 × 方向，输出笔数/胜率/PnL
3. **分半年稳定性**：2024H1 / 2024H2 / 2025H1 / 2025H2 / 2026H1 各方向的胜率
4. **分时段**：北京时区每小时胜率
5. **组合方案**：只做DOWN / UP≥0.58+DOWN / 只DOWN≥0.57 等的全期 PnL 对比

## 产出物

- `v7_backtest.py` — 独立回测脚本（放项目根目录）
- 运行输出报告（控制台 + 可选保存文件）

## 决策标准

- 若 UP 在多数半年期都 ≤55%，确认方向过滤有效
- 选定的方向/阈值组合需在分半年上胜率稳定 ≥60%，避免单期运气
- 最终配置建议（阈值 JSON + 方向过滤代码）在回测确认后另行实施

## 不做的事

- 不重训模型（训练脚本不在包内）
- 不修改 V7 服务器代码（本阶段只读验证）
- 不做多币种（模型只支持 ETHUSDT）
